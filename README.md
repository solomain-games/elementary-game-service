# Elementary — игровой сервис (game-service)

Комнаты, партии и реалтайм (WebSocket) игры **Elementary**. Правила игры берутся из библиотеки `game-core`, состояние партий хранится в Redis.

## Запуск локально

Требуется JDK 25 и запущенный Redis из [`elementary-infra`](https://github.com/solomain-games/elementary-infra) (`local/docker-compose.yml`).

```powershell
.\mvnw spring-boot:run
```

Сервис стартует на порту **8081** с профилем `local`.

Проверка: http://localhost:8081/actuator/health → `"status": "UP"`, в `components` виден `redis`.

Запросы с токеном — в `http/auth.http` (нужен запущенный user-service).

## Дела

При старте сервис загружает все дела из папки `elementary.cases.dir`: каждая подпапка с `case.json` — одно дело (формат — в README репозитория `elementary-cases`). Локально это соседний репозиторий: `../cases/cases`.

Каждое дело проверяется: поля и значения, существование файлов, переводы на все объявленные языки, ссылки `[[15]]` на существующие карты. Дело с ошибками пропускается, а в логе перечислены все его ошибки. Если нет самой папки — сервис не запускается.

`GET /api/game/cases` — список дел для выбора в комнате (протокол, 4.2).

## Комнаты

REST зала ожидания (протокол, 4.4–4.6): `POST /api/game/rooms` — создать, `GET /api/game/rooms/{code}` — сведения, `.../join`, `.../leave`, `.../kick`, `.../start`. Сценарий целиком — в `http/rooms.http`.

- Комната хранится в Redis под ключом `room:{код}` в виде JSON. Срок хранения (`elementary.rooms.ttl`, 6 часов) продлевается при каждом изменении, заброшенные комнаты Redis удаляет сам.
- Изменения одной комнаты выполняются по очереди (`RoomLocks`), поэтому одновременные входы не затирают друг друга. Замки работают внутри одного процесса: для нескольких экземпляров game-service понадобится блокировка в Redis.
- `start` пока только переводит комнату в `IN_GAME`; раздача и партия — в Г6 и Г7. Выход из идущей партии — там же.

## WebSocket

STOMP на `/ws` (протокол, раздел 5).

- Подписки: `/user/queue/state` (личные снимки), `/user/queue/errors` (ошибки своих команд), `/topic/room.{код}` (события комнаты). На события комнаты может подписаться только её участник (`RoomSubscriptionInterceptor`), иначе — кадр `ERROR` с `NOT_IN_ROOM`.
- После каждого изменения комнаты `RoomBroadcaster` отправляет событие в канал комнаты и каждому участнику — его снимок. Команда `sync` присылает снимок по запросу.
- «В сети»: игрок подписан на события комнаты хотя бы из одной вкладки (`RoomPresence`). Подключение и отключение рассылают свежие снимки.
- Пульс 10 с; кадры одной сессии обрабатываются по порядку.
- Игровые команды пока отвечают `GAME_NOT_STARTED` — партии появятся в Г7.

## Аутентификация

Токены выпускает user-service (ADR 0003), game-service проверяет их сам открытым ключом из JWKS user-service. Ключ скачивается при первой проверке и кешируется, поэтому сервис запускается и без user-service, но для запросов с токеном user-service должен работать.

| Где | Как передаётся токен | Ошибка |
|---|---|---|
| REST | `Authorization: Bearer <token>` | `401`, Problem Details с `code: UNAUTHORIZED` |
| WebSocket `/ws` | заголовок `Authorization` в кадре STOMP `CONNECT` | кадр `ERROR` с `message:UNAUTHORIZED`, разрыв соединения |

Игрок определяется только по токену: `sub` — id игрока, `role` — роль (`ROLE_GUEST`). Без токена открыты только `/actuator/health/**` и `/actuator/info`.

## Профили

| Профиль | Где | Настройки |
|---|---|---|
| `local` (по умолчанию) | компьютер разработчика | `application-local.yaml`: Redis на `localhost:6379` |
| `prod` | боевой сервер | `application-prod.yaml`: значения из переменных окружения (ниже) |

Переменные окружения `prod`:

| Переменная | Что это |
|---|---|
| `REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD` | подключение к Redis |
| `CASES_DIR` | папка с делами |
| `JWKS_URI` | адрес открытого ключа user-service, например `http://user-service:8082/.well-known/jwks.json` |
| `WEBSOCKET_ALLOWED_ORIGINS` | адрес сайта, с которого можно открыть WebSocket; несколько — через запятую |

Профиль задаётся переменной `SPRING_PROFILES_ACTIVE`.

## Сборка и тесты

```powershell
.\mvnw verify
```

Тесты запускаются с профилем `test`: дела берутся из `src/test/resources/test-cases` (копия дела-заглушки), другие сервисы и соседние репозитории не нужны.
